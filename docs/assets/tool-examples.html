rsync

Copy a file

rsync 3.2.3+

rsync -t --mkpath --modify-window=-1 report.csv server:/backup/

syq

syq cp report.csv --to server --into /backup

Copies report.csv to /backup/report.csv on server.

Differences

With --modify-window=-1, rsync compares modification times to the nanosecond. Syq accepts differences below the precision suggested by the destination timestamp; for example, a destination time ending in .000000000 ignores the source’s fractional second when checking for an unchanged file.

Send a folder to a server

rsync 3.2.3+

rsync -rlt --mkpath --modify-window=-1 project server:/backup/

syq

syq cp project --to server --into /backup

Copies project to /backup/project. Other entries in /backup stay.

Differences

With --modify-window=-1, rsync compares modification times to the nanosecond. Syq accepts differences below the precision suggested by the destination timestamp; for example, a destination time ending in .000000000 ignores the source’s fractional second when checking for an unchanged file.

Rsync can replace an empty destination directory with a source file. Syq refuses file/directory type conflicts, even for empty directories.

Copy the files inside a folder

rsync 3.2.3+

rsync -rlt --mkpath --modify-window=-1 project/ server:/backup/

syq

syq cp --srcs-in project --to server --into /backup

Copies project/index.html to /backup/index.html. Destination-only files stay.

In rsync, project/ copies the contents; project copies the folder. In syq, a trailing slash does not change placement: use --srcs-in for contents.

rclone

Copy a file

rclone

rclone copyto report.csv s3:backups/reports/report.csv

syq

syq cp report.csv --to s3://backups --as reports/report.csv

Uploads report.csv to reports/report.csv in bucket backups.

Here s3 is an rclone S3 remote. Syq uses AWS credentials and its own endpoint settings. Existing objects can be replaced.

Differences

When sizes match but modification times differ, rclone can compare available hashes and update only the timestamp if the contents match. Syq’s default unchanged-file check uses size and modification time, without that hash fallback.

Rclone stores source modification times in S3 metadata named mtime; syq uses syq-mtime and syq-mtime-nsec. Each tool restores its own timestamp format; one tool’s upload does not give the other the same source-time information.

Copy the files inside a folder

rclone

rclone copy --links --create-empty-src-dirs project backup

syq

Copies project/index.html to backup/index.html. Destination-only files stay.

Differences

When sizes match but modification times differ, rclone can compare available hashes and update only the timestamp if the contents match. Syq’s default unchanged-file check uses size and modification time, without that hash fallback.

Without --metadata, rclone does not restore source Unix permission bits. Syq gives new files the source read/write/execute bits limited by the destination umask and keeps existing destination permissions. Rclone’s --metadata would additionally restore ownership and other metadata, so it does not match syq’s default either.

Copies report.csv from bucket backups to bucket archive.

Here s3 is an rclone S3 remote. Both buckets must exist on the same S3 service for this syq example.

Differences

Rclone’s default skip decision uses size and modification time, with a hash comparison when times differ. Syq checks object type, size and copyable metadata, then compares full-object checksums when available; otherwise, it accepts matching ETags or a source carrying syq metadata. These tests can make different decisions about whether to copy an existing object.

Differences

S5cmd cp copies selected files again even when the destination already matches. Syq can skip unchanged entries. S5cmd’s size-only and source-newer conditions do not reproduce syq’s default comparison.

S5cmd uploads regular file contents without automatically recording source Unix permissions or modification times. Syq records those in its S3 metadata and restores modification times on download.

scp

syq

syq cp report.csv --to server --into /backup

Differences

Scp -p preserves source permission bits and access times as well as modification times. Syq preserves modification times, leaves existing destination permissions alone, and creates files with source read/write/execute bits limited by the destination umask; it does not preserve source access times.

Scp transfers each file again and writes directly to the destination. Syq can skip unchanged files and normally stages changed files before replacing them, keeping the old file available until replacement.

The scp destination directory must already exist for the placement shown. Syq creates missing destination directories.

Download a folder from S3

syq

syq cp --from s3://backups --srcs-in reports --into reports

Downloads reports/january.csv from S3 to reports/january.csv locally, keeping subfolders.

Copy a file between S3 buckets

syq

syq cp --from s3://backups report.csv --to s3://archive --as report.csv

Copies report.csv from bucket backups to bucket archive.

Both buckets must exist on the same S3 service for this example.

Remove a file

syq

syq rm --on s3://backups old.csv

Removes the object old.csv from bucket backups.

Preview with --dry-run -v. Bucket versioning affects recovery.

Send from a server shell to a laptop with no SSH server

syq

# On the server:
syq cp results --to @laptop

Sends results home from the server shell. Your laptop needs no SSH server or incoming port.

Set up the receiving name laptop, then approve the copy on your laptop.

Alternatives that change the task

Rsync, scp, and rclone can pull from the laptop instead. S5cmd can stage files in S3.

Copy directly between servers without agent forwarding

syq

# On your laptop:
syq cp --from hostA --srcs-in results --to hostB --into results

Uses your laptop’s SSH logins. Files travel directly between servers; neither server gets your keys or access to your SSH agent.

The servers need a connection to each other. Setup.

Alternatives that change the task

Scp -3 and rclone relay through your laptop. Rsync on hostA or scp -R requires hostA to have its own access to hostB. S5cmd can stage files in S3.
