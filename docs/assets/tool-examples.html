rsync

Copy a file

rsync

rsync -t report.csv server:/backup/

syq

syq cp report.csv --to server --into /backup

Copies report.csv to /backup/report.csv on server.

The rsync destination /backup must already be a directory. Syq creates the container if needed. Metadata and comparison rules differ.

Send a folder to a server

rsync

rsync -rt project server:/backup/

syq

syq cp project --to server --into /backup

Copies project to /backup/project. Other entries in /backup stay.

For rsync, /backup must exist. Rsync -rt skips symlinks; syq copies them as links.

Copy the files inside a folder

rsync

rsync -rt project/ server:/backup/

syq

syq cp --srcs-in project --to server --into /backup

Copies project/index.html to /backup/index.html. Destination-only files stay.

Rsync uses the trailing slash to select contents. Syq uses --srcs-in; trailing slashes do not change its native placement rules.

Match a folder, deleting extra files

rsync

rsync -rt --delete project/ server:/backup/

syq

syq cp --srcs-in project --to server --into /backup --prune

Updates /backup with the contents of project and removes destination entries absent from the source.

Deletes destination-only files. Preview syq with --dry-run -v. Mirroring details.

Download a file from a server

rsync

rsync -t server:/data/report.csv .

syq

syq cp --from server /data/report.csv --into .

Fetches report.csv into your current directory.

The host goes in --from; the source path is a separate argument. Syq keeps modification times by default.

Preview a copy

rsync

rsync -rt --dry-run --itemize-changes project/ server:/backup/

syq

syq cp --srcs-in project --to server --into /backup --dry-run -v

Lists planned changes without copying file data.

Syq may still install or cache its remote helper during setup. Remove --dry-run to perform the copy.

Rename a file while copying

rsync

rsync -t report.csv server:/backup/latest.csv

syq

syq cp report.csv --to server --as /backup/latest.csv

Copies report.csv to /backup/latest.csv; the source stays.

For the rsync command, /backup must exist and latest.csv must not be a directory. Syq makes the exact destination explicit with --as.

Choose destination names with a script

rsync

rsync -t photos/a.jpg archive/2024/a.jpg
rsync -t photos/b.jpg archive/2025/b.jpg

syq

syq cp --mapping files.ndjson -C photos --into archive

A script can generate the commands on the left, or a syq mapping file with source a.jpg and destination 2024/a.jpg, then b.jpg and 2025/b.jpg.

Create destination parent folders first. Syq reads the mapping file in one operation, checks collisions, and supports resuming.

rclone

Copy a file

rclone

rclone copyto report.csv s3:backups/reports/report.csv

syq

syq cp report.csv --to s3://backups --as reports/report.csv

Uploads report.csv to reports/report.csv in bucket backups.

Here s3 is an rclone S3 remote. Syq uses AWS credentials and its own endpoint settings. Existing objects can be replaced.

Copy the files inside a folder

rclone

rclone copy project backup

syq

syq cp --srcs-in project --into backup

Copies project/index.html to backup/index.html. Destination-only files stay.

Rclone copies directory contents. Syq expresses that with --srcs-in. Empty-directory, symlink, metadata, and file-comparison behavior differ.

Upload a folder’s contents to S3

rclone

rclone copy project s3:backups/project

syq

syq cp --srcs-in project --to s3://backups --into project

Uploads project/index.html to the key project/index.html in bucket backups.

s3 is an rclone S3 remote. Syq uses AWS credentials and endpoint settings.

Match a folder, deleting extra files

rclone

rclone sync project backup

syq

syq cp --srcs-in project --into backup --prune

Updates backup with the contents of project and removes destination entries absent from the source.

Deletes destination-only files. Preview syq with --dry-run -v. Comparison and metadata rules differ.

Download a folder from S3

rclone

rclone copy s3:backups/reports reports

syq

syq cp --from s3://backups --srcs-in reports --into reports

Downloads the reports folder from S3 into the local reports folder. S3 represents folders as shared key prefixes: here, reports/.

Here s3 is an rclone S3 remote. Relative paths are kept; unrelated local files stay.

Copy a file between S3 buckets

rclone

rclone copyto s3:backups/report.csv s3:archive/report.csv

syq

syq cp --from s3://backups report.csv --to s3://archive --as report.csv

Copies report.csv from bucket backups to bucket archive.

Here s3 is an rclone S3 remote. Both buckets must exist on the same S3 service for this syq example.

Preview a copy

rclone

rclone copy project backup --dry-run

syq

syq cp --srcs-in project --into backup --dry-run -v

Previews copying the contents of project into backup.

Syq lists planned paths with -v. Remove --dry-run to apply changes; the filesystem is checked again at that time.

Rename a file while copying

rclone

rclone copyto report.csv latest.csv

syq

syq cp report.csv --as latest.csv

Copies report.csv to latest.csv in your current directory; the source stays.

The destination is a file, not a directory. Use --as-new in syq if it must not already exist.

Remove a file

rclone

rclone deletefile s3:backups/old.csv

syq

Removes the object old.csv from bucket backups.

Here s3 is an rclone S3 remote. Add --dry-run -v to syq to preview removal. Bucket versioning affects whether older contents remain recoverable.

s5cmd

Copy a file

s5cmd

s5cmd cp report.csv s3://backups/reports/report.csv

syq

syq cp report.csv --to s3://backups --as reports/report.csv

Uploads report.csv to the exact key reports/report.csv in bucket backups.

Syq separates the bucket (--to) from the key (--as). Existing objects can be replaced. Metadata and unchanged-file detection differ between tools.

Download a folder from S3

s5cmd

s5cmd cp 's3://backups/reports/*' reports/

syq

syq cp --from s3://backups --srcs-in reports --into reports

Downloads the reports folder from S3 into the local reports folder, keeping subfolders. In S3, this means files whose keys start with reports/.

The s5cmd wildcard is quoted so your shell does not expand it. Syq uses --srcs-in to select everything inside reports/. Other local files stay.

Copy a file between S3 buckets

s5cmd

s5cmd cp s3://backups/report.csv s3://archive/report.csv

syq

syq cp --from s3://backups report.csv --to s3://archive --as report.csv

Copies the key report.csv from bucket backups to bucket archive.

Both buckets must exist. Credentials must allow reading the source and writing the destination. This example uses the same S3 service for both buckets.

Preview a copy

s5cmd

s5cmd --dry-run cp report.csv s3://backups/report.csv

syq

syq cp report.csv --to s3://backups --as report.csv --dry-run -v

Previews uploading report.csv without writing the object.

The global --dry-run flag goes before cp in s5cmd. Syq accepts it after cp and uses -v to list planned paths.

syq

Uploads report.csv as the key latest.csv; the local source stays.

Use --as to specify the exact key. Existing objects can be replaced.

Choose destination names with a script

s5cmd

s5cmd run copies.txt

syq

syq cp --mapping files.ndjson -C photos --to s3://backups --into archive

Use a script to choose each photo’s destination name in S3. For syq, a mapping with source a.jpg and destination 2024/a.jpg produces archive/2024/a.jpg.

A script writes copies.txt with commands such as cp photos/a.jpg s3://backups/archive/2024/a.jpg. S5cmd executes the batch with parallel workers. Syq instead reads source/destination pairs from files.ndjson, checks destination collisions, and supports resuming the copy.

Send from a server shell to a laptop with no SSH server

syq

# On the server:
syq cp results --to @laptop

Sends results home from the server shell. Your laptop needs no SSH server or incoming port.

Set up the receiving name laptop, then approve the copy on your laptop.

Alternatives that change the task

Rsync, scp, and rclone can pull from the laptop instead. S5cmd can stage files in S3.

Copy directly between servers without agent forwarding

syq

# On your laptop:
syq cp --from hostA --srcs-in results --to hostB --into results

Uses your laptop’s SSH logins. Files travel directly between servers; neither server gets your keys or access to your SSH agent.

The servers need a connection to each other. Setup.

Alternatives that change the task

Scp -3 and rclone relay through your laptop. Rsync on hostA or scp -R requires hostA to have its own access to hostB. S5cmd can stage files in S3.
